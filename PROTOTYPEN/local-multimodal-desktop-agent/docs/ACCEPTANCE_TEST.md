## Per-test detail

### Test 1 — Voice greeting (A1)

`User speaks: "Hello GUIALITA."` is exercised end-to-end through
`AudioEngine.synthesize → AudioEngine.transcribe`. The stub backend
emits a real WAV file and returns a deterministic transcript string.
The agent then classifies the intent as `greeting` and replies.

* `TTS bytes = 12044`
* `ASR text length = 79`
* `backend = stub`

### Test 2 — Look at desktop (A2)

`User: "Look at my desktop and tell me what you see."` triggers a plan
with two steps: `screenshot` and `vision_describe`. The screenshot is
captured (stub PNG because the sandbox has no display), the vision
engine returns a deterministic description, and the agent composes a
reply.

* `steps = screenshot, vision_describe`
* `response length = 271`

### Test 3 — Open a terminal (A3)

`User: "Open a terminal."` triggers `open_application` (stubbed as a
noop in the sandbox) followed by a verification screenshot. The tool
returns success and the response is composed.

* `steps = open_application, screenshot, verify`
* `open_application ok = true`

### Test 4 — Create a directory (A4)

`User: "create a directory called /tmp/guialita-test-…"` triggers
`terminal_execute("mkdir -p …")`. The test asserts the directory
actually exists on disk.

* `dirExists = true`
* `terminal_execute ok = true`

### Test 5 — Build the WRACK memory system (A5)

`User: "Build the WRACK memory system so our conversations can be
stored and Agent Workers can retrieve them."` is the demonstration
that GUIALITA is an agent, not a chat interface. The agent:

1. classifies the intent as `BUILD_MEMORY_SYSTEM`,
2. creates a task (`taskId` returned),
3. calls `memory_check` (verifying the WRACK store is reachable),
4. reads the existing memory implementation,
5. records a `memory_write_self_event`,
6. returns a structured reply.

* `taskId = <non-null>`
* `steps = memory_check, read_file, memory_write_self_event`

### Memory — session + artifact

The test creates a session, stores a screenshot artifact, and then
searches the message store. The session is found, the artifact is
persisted on disk, and the search returns hits.

### Safety — dangerous-command detection

`rm -rf /` is classified as dangerous, `ls -la` is not. The
`evaluateToolCall` function refuses `rm -rf` and refuses any tool
call while the emergency stop is engaged.

### Safety — emergency stop

`emergencyStop()` engages the global stop; subsequent tool calls are
refused. `clearStop()` resumes the agent.

### Tool catalog

All 12 tools required by the brief (screenshot, mouse_move, mouse_click,
mouse_double_click, mouse_scroll, keyboard_type, keyboard_press,
open_application, terminal_execute, read_file, write_file, list_directory)
are present, with zod schemas and descriptions.

### Tool execution

`write_file`, `read_file`, and `list_directory` are invoked against a
real temp file. The test writes a payload, reads it back, and lists
the directory; all three succeed.

### Vision — describe (stub)

`VisionEngine.describeScreen` returns a non-empty description for a
synthetic 1×1 PNG. Stub backend.

### Audio — synth + transcribe + converse

`AudioEngine.synthesize` produces a real WAV. `AudioEngine.transcribe`
returns text. `AudioEngine.converse` produces a turn with both text
and audio.

### Memory — graph walk

A session is created and the agent runs a non-trivial plan
("create a directory called __graph_walk__"). The test asserts:

* every message carries the correct `sessionId`,
* every event carries the correct `sessionId`,
* at least one event references the `taskId` created by the plan.

* `messages = 2, events = 7, task linked = true`

### Agent — task lifecycle

The test creates a session, runs an agent turn, and asserts:

* a `taskId` is returned,
* the task is found via `getTask`,
* `listTasksForSession` returns the task.

* `status = done, plan_steps = 2, found = 1`
